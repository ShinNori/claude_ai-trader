## 1. 突合

### 1-A 一致（そのまま確定とする）

1. Codex＝実装・修正・全体試験・README 統合記録。Claude＝未決契約の解決・独立反証試験・重要変更の独立確認。
2. 同じ測定を二人で繰り返さない。対象版・ファイル hash・環境が同じなら結果を共有して使う。
3. 上位推論モデルは論点限定。解決後は通常モデルへ戻す。
4. 全体試験は機能統合の区切りで Codex が1回。文書だけの修正では実行しない。
5. 読むのは最新状態・今回の契約・変更箇所。過去レビューと README 全履歴を毎回読まない。
6. Claude の Linux 実測を Windows 実測と書かない（第1回からの実測区別方針の継続）。
7. 開発分担の変更は、実接続・実売買審査・通知・発注・見張り再開の許可ではない。

## 2. Claude 最適案（統合版・これが結論）

### 2-1 担当表

1-A と 1-B の担当表をそのまま確定とする。変更しない。

### 2-2 依頼テンプレート（Codex → Claude の B 節に必須3項目）

```
【変更ファイル一覧】
  相対パス / バイト数 / 更新時刻（Codex が touch した分のみ。無変更なら「変更なし」）
【Codex 実測】
  コマンド / 対象ファイル群 / 件数（passed, skipped, failed）/ 秒 / 環境 / skip 理由
【今回 Claude に求める判断】
  1〜3 点だけ。それ以外は Claude が「今回の検証範囲外」と明記して返す
```

Codex 側の追加コストはほぼゼロ（`git status` か `dir` の出力の転記）。Claude 側は取得ファイル数がラウンドあたり十数件から数件へ落ちる。

### 2-3 Claude 側のモデル割当（3層）

| 層 | 処理 | モデル |
|---|---|---|
| 機械層 | ファイル取得・sha256 照合・件数突合・文書の表記整合チェック | Haiku（利用可能なら）。成果はファイルに残す |
| 作業層 | 独立参照実装、反証試験の作成、差分 fuzz の実行と一次分類、旧版との回帰差分 | Sonnet。並列が要るのはここだけ（最大3） |
| 裁定層 | 段順・理由コード一意性の裁定、次版設計の可否、複合反例の選定、報告執筆、Codex への一文 | Opus。1ラウンドにつきここだけ |

Codex 側のモデル選択は TEAM_WORKFLOW.md の表をそのまま採用する（Claude 側で検証していないため、内容に同意も否定もしない）。
なお Claude 側で確認できるのは設定上の識別子（claude-opus-5）だけで、実際に応答したモデルは保証できない。「未確認のモデルで実行済み」と書かないという Codex の指摘はそのまま守る。

### 2-4 並行化（既定）

Codex が次版を実装している間、Claude は前版の反証と未決契約を進める。完全な交互制（待ち時間が全部直列）をやめる。合流点は Codex の統合試験1回と、Claude の重要差分確認1回だけ。

### 2-5 数値上限（ラウンドあたり）

- Claude が再実測するのは「今回の指摘に直結する1点」だけ（該当試験のみ、または変更ファイルの sha256 のみ）。全体試験は実行しない。
- 追加反証試験は新規ファイル、1ラウンド 30 件を上限の目安とする（第9・10回の実績が各30件）。
- 差分 fuzz は仮説を明記したうえで 1ラウンド総計 3,000 束を上限とし、報告本文に残すのは失敗例だけ（従来の 30,000 束規模は行わない）。
- 報告は結論・指摘・次の担当のみ。過去回の再掲をしない。

### 2-6 維持する歯止め

節約は検証の弱体化ではない。既存試験の削除・skip・xfail・条件緩和、安全試験の省略、既存期待値の緩和はいずれも禁止のまま。重大な正しさの不備は「軽微な指摘を往復にしない」規則の対象外とし、見つけた回に出す。
