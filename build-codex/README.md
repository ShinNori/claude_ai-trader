# ai-trader — Codexビルド（フェーズ0〜1）

共通仕様に基づく日次の研究用シグナル・バックテスト基盤。フェーズ2として判定パケット生成を追加した。共通の合成データを使用し、A1の既定パラメータを固定した。LINE配信・AI審査・証券接続・発注は実装していない。

## セットアップ

Python 3.11以上を使用する。以下はこのフォルダをカレントにして実行する。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
$env:AI_TRADER_HOME = Join-Path $env:LOCALAPPDATA 'ai-trader-codex'
python -m aitrader init-db
python -m aitrader load-synthetic --seed 42
python -m aitrader signals --strategy margin_bucket_long --as-of 2025-06-06
python -m aitrader backtest --strategy margin_bucket_long --from 2016-01-04 --to 2026-08-31 --out results/
python -m aitrader report --results results/margin_bucket_long_v1/
python -m pytest ../common/tests -q
python -m pytest tests -q
```

Linuxでは仮想環境を`source .venv/bin/activate`で有効にし、`export AI_TRADER_HOME="$HOME/.ai-trader-codex"`を設定する。

AI_TRADER_HOME省略時は`~/.ai-trader/`。Claudeビルドと別の実行先を使う。CLIの出力先が共有ソース配下なら、取引・資産CSV本体はAI_TRADER_HOME/resultsへ保存し、summary.jsonとreport.htmlだけを指定先へコピーする。公開APIはテスト互換のため明示されたout_dirへ4ファイルを書き込むので、外部の実行先を指定すること。

## 公開API・構成

`aitrader.api`はinit_db、load_synthetic、run_signals、run_backtestを共通仕様の引数で提供する。run_signalsのdict内のas_ofはdate型で、CLIでJSON文字列へ変換する。

- db.py：DuckDBスキーマと接続、データ出所の管理。
- strategies/：Candidate型、戦略インターフェース、A1、登録関数。
- backtest.py：寄り付き買付→終値売却→時価評価の順に処理。
- jquants.py：共通仕様の旧v1データ形式のクライアント・ETL。
- report.py：外部通信不要の単一HTML。
- tests/：取込の重複・失敗・混在防止、日中の資金処理順序のテスト。

## 仕様の解釈表

| 論点 | Codex実装の解釈 |
|---|---|
| 毎週月曜・休場 | 全データ上のISO週の最初の営業日を採用。期間開始が週途中でも臨時リバランスしない |
| 営業日 | prices_dailyに存在する日付。合成カレンダーは実際の東証休日の完全再現ではない |
| as_of | エントリー日の直前の価格営業日。休日指定のsignalsは指定日時点までの情報を使用 |
| ユニバース | prime/standard、上場から暦年1年以上、全体の直近60営業日すべてに価格があり平均売買代金1億円以上 |
| 信用残の4週前 | 公表済みかつ観測日がas_of以前の最新5本について、最新÷5本前。週抜けがある実データでは別途品質検証が必要 |
| 分位 | 有効なユニバースをchg4w昇順、同点はcode昇順。先頭floor(N/5)、最大20銘柄 |
| 20日保有と毎週入替 | 各週に新規候補を追加し、既存保有は20営業日後まで維持。「毎週全売却」は行わない |
| 同一銘柄 | 保有済みなら重複スキップ。朝時点で保有なら当日終値で売る予定でも買い直さない |
| 利用可能資金 | 寄り付き直前の現金÷候補数。未約定・重複分を他候補へ再配分しない |
| 日中の処理順 | 朝の買付が先、終値の売却が後。同日の終値売却代金を朝の買付には使わない |
| 指値 | 前営業日終値×1.005と寄り値を比較。上回れば未約定。スリッページは共通仕様どおり別途価格へ反映 |
| スリッページ | 買いopen×1.001、売りclose×0.999。これは比較用のコストモデルで、指値保証の実約定モデルではない |
| 株数・資金 | 金額÷コスト込み価格の端株。整数単元・実口座余力はフェーズ1で扱わない |
| 売却日 | エントリー日を0として20営業日後の終値。期間末は残保有を強制決済。最終日の新規候補も同日終値決済となり得る |
| 欠損価格 | 評価は最後の確認済み終値を使用。必要な売却価格が欠けた場合は架空の約定を作らずエラーにする |
| 指標 | CAGRは252/実価格日数、シャープは標本標準偏差・rf=0。初日の初期資金比リターンも含める |
| DD・年別 | 初期資金もピークの候補。年別リターンは前年末資産から、件数はエントリー年で集計 |
| 損失なしのPF | JSONのnull。NaNやInfinityをJSONに出さない |
| 再現性 | 候補・価格の順序固定、DB単一スレッド。generated_at以外は同じ入力で決定的に計算 |
| データ区分 | provenanceにsynthetic/jquantsを明示。出所不明ならバックテストを停止 |

## J-Quantsの範囲と制限

`fetch --from ... --to ...`は環境変数JQUANTS_REFRESH_TOKENを使用する。.env.exampleは記入項目の見本であり、.envの自動読込は行わない。実行環境の秘密情報設定から環境変数を渡す。

共通仕様にある旧v1の認証・ページング・価格・信用残・銘柄・TOPIX・カレンダー取得を実装した。全取得・変換成功後にトランザクションで反映し、同じキーは更新する。合成DBへの実データ追記は禁止する。価格は調整済みOHLCが揃うときに優先し、信用残の公表日列がない場合は仕様の基準日+4暦日を推定値として記録・警告する。

**現行サービスへの接続試験は未実施。** 公式旧仕様ページの取得では本文を確認できず、契約も未登録。想定API形式が変わった場合は停止する。トークンがあるだけで現行サービスの利用を保証しない。銘柄情報に上場日がない場合は捏造せずNULLにし、上場年数条件から除外するため、確認済み上場日が別途必要になる。価格欠損はこの段階では取込を止める。公表日推定・最新銘柄マスタ・価格調整履歴には本番研究に向けた追加検証が必要。

参考（本文取得が不十分だったため実装の根拠は共通仕様）：https://jpx.gitbook.io/j-quants-ja/api-reference/daily_quotes

## フェーズ2：判定パケットと独立受入テスト（2026-09-08）

現在の主系はbuild-codex。Claudeはops/の台帳・ゲートを担当し、Codexは先に受入テストを作る分担。共通の3テストファイルをpacket.py実装前に作成した。フェーズ1の比較条件・パラメータは変更していない。

### 追加機能

```powershell
python -m aitrader packets --strategy margin_bucket_long --as-of 2025-06-06
python -m aitrader packets --strategy margin_bucket_long --as-of 2025-06-06 --budget-per-name 250000 --policy-version review-v1 --events events.json --lot-sizes lots.json
```

標準出力はProposalのJSON配列。期限はISO8601のJST、警告・除外理由は標準エラーへ出す。既定予算25万円/銘柄は研究用の生成条件であり、資金配分の承認を意味しない。単元未満は除外する。ゲート適用・通知件数制限・実資金の予約・通知はここでは行わない。

events.jsonの形：`{"6857":{"next_earnings_date":"2026-10-01","margin_regulated":false}}`。lots.jsonの形：`{"6857":100}`。日付は例であり実際の企業情報ではない。未指定イベントはUNKNOWN、単元のCLI既定値100は研究用。実運用では確認済み値が必要。

### 公開API

- `aitrader.packet.build_proposals(...)`：共通仕様の引数に加え、任意の`business_days=[date(...), ...]`を受け付ける。ops未実装でも使える、同じ属性契約のローカルProposal dataclassを返す。
- `packet_hash(p)`：仕様の14フィールドのみを正規化してSHA256。reason/eventsを含めないという仕様を厳守する。
- `render_packet(p,market_context)`：JSON本文。UNKNOWNを明示し、自由資料をreferenceへ分離する。他AIの判定フィールドの混入や古いhashでの描画を拒否する。
- `packet_cli.generate(...)`：市場DBを読み、候補・価格・単元・イベント等からsnapshot_idを算出してProposalを生成する。台帳・証券には接続しない。

### 追加の解釈・未確定点

| 項目 | 実装・制限 |
|---|---|
| BUYの呼値 | +0.5%上限を超えないようDecimalで切り下げ。簡易呼値はraw<1000が1円、raw<=5000が5円、超過が10円 |
| 数量 | `floor(予算/(指値×単元))×単元`。boolや負数等は入力エラー |
| 営業日 | CLIはDBのcalendarにある次営業日を使用。不足なら停止。公開APIのカレンダー省略は平日のみの研究用互換動作 |
| ID | 候補を戦略・版・codeでソートし、執行日のJST日付と連番を使う。重複候補は拒否 |
| SELL生成 | 保有数量と売り指値の入力契約がないため明示エラー。ゲートのSELL試験は別途用意 |
| 型共有 | packet側のProposalはops側の同名型と属性互換。opsを任意importして動作を変えない |
| スナップショット | CLIでは資料値からhashを生成。手動API呼出しではsnapshot_idの正確性は呼び出し元の責任 |
| 未定義のops入力型 | SimpleNamespaceによる属性レコードをテスト入力として提案。正式な型・日次損失入力・部分約定qty等の課題をcommon/ISSUES.mdに記載 |
