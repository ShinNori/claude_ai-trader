# 開始残高の平均取得価格：入力監査の未決事項

2026-09-11、Codexの限定読取監査。**負の平均取得価格を開始残高が受容することを実測した。** 受容を正しい契約と認定するものではなく、拒否へ変更する採用判断もまだ行っていない。コード・共通仕様は変更せず、この動作を肯定する回帰テストも追加していない。

## 最小の実測証拠

Dropbox外の一時SQLite台帳で、公開 `Ledger.init_snapshot` に次を指定した。台帳は確認後に閉じ、一時保存先は破棄した。

```python
ledger.init_snapshot(
    1_000_000,
    [{'code': '6857', 'qty': 100, 'avg_price': -1}],
    [],
    datetime(2026, 9, 11, tzinfo=timezone.utc),
)
```

例外なく終了し、`ledger.positions()['6857']` は `qty=100, avg_price=-1.0`、現金は1,000,000円、予約額は0円だった。実口座・ネットワークは使用していない。

## 現在の規則と影響範囲

[共通仕様の台帳API](../common/共通仕様_フェーズ2.md) は開始残高にPositionInを受け、positionsからavg_priceを返す契約を持つ。[models.py](../ops/aitrader_ops/models.py) のPositionInはavg_priceをfloatと宣言するが、それだけで正値検証は行われない。

[ledger.py](../ops/aitrader_ops/ledger.py) の `_on_snapshot` は保有数量の正値を検証する一方、平均取得価格は `_money(pos.get('avg_price', 0), 'avg_price') * qty` で簿価へ変換する。欠損時には0を使う。この経路で負値を拒否する検査がないため、今回の値が残った。追加した純粋 `validate_snapshot_for_replay` は既存replay規則を再利用するため、独自にこの値を拒否するものではない。

[gate.py](../ops/aitrader_ops/gate.py) は既存保有額の判定に数量×平均取得価格を使う。従って負の簿価が評価に入り得ることはコード上の検討事項である。ただし今回の実測はsnapshot受容までで、特定の不適切な売買承認や損失を再現したものではない。現行の合成pipelineは初期保有なしであり、この負値がそこで発生する影響は未実証である。

## 採用前に決めること

| 論点 | 確認すべき契約 |
|---|---|
| 負値 | 保有の取得価格として一律拒否するか。調整額など別概念を同じ欄へ入れていないか。拒否するなら新規入力境界と履歴replayを区別する |
| 0 | 無償取得等の実務上の意味を認めるか、単に未確認値として停止するか。負値と一括扱いしない |
| 欠損 | 現在の既定0を継続するか、明示的な不明状態を持たせるか。未確認の価格を確認済み0へ黙って変換しない |
| 型・非有限値 | bool・文字列・NaN・無限大を各入力経路でどう統一するか。JSONとDBと純粋検証の差を試験する |
| 移行・履歴 | 新規snapshotだけを厳格化する場合も、過去履歴を読み戻せなくしない方針が必要。既存負値の検出・照合・訂正履歴を定め、原本を自動修正しない |
| provenance | 照合済み開始残高の出典・cutover遮断と、取得価格の妥当性は別問題。provenanceがあるだけで値を正しいと扱わず、照合対象に取得価格を含むか明示する |

採用する場合は現物保有・外部注文・移行済み開始残高・再open/replayを含めた試験と、ゲート集中度への影響確認を行う。負値を0や絶対値へ自動補正する案は原本の意味を変えるため推奨しない。

この所見だけで、実口座未接続・初期保有なしの現行合成開発を停止必須とは判断しない。実保有を取り込む前の未決契約として追跡する。最新の全体試験結果は [README](README.md) を参照する。
