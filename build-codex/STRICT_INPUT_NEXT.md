# 専用入力の次段階と証拠の不足

2026-09-12。strict_input_v1は人工入力の整合検査まで実装済み。本書は残工程の設計整理であり、新しい適格性規則やDB取込の採用記録ではない。既存の正確な契約は[STRICT_INPUT.md](STRICT_INPUT.md)。

| 残工程 | 次に必要な入力・判断 | オフラインで確認する境界 | 現在保証していないこと |
|---|---|---|---|
| 価格の鮮度 | 呼出側が期待する取引日・締切と、その根拠となる営業日情報 | 古い値・未来値・休場日・別timezoneの同一時点 | 「as_of以前」だけで最新営業日のデータと扱わない |
| 単元の有効期間 | 銘柄別の適用開始・終了、境界の包含規則、原本参照 | 境界直前/同時刻/直後、期間重複、空白期間、銘柄差 | 正の整数であっても対象日時の単元とは限らない |
| 公表時刻の出所 | 行の公表日時と原本項目の意味、取得日時との区別 | 推定/予定/取得時刻の混同、原本差替え、後日訂正 | estimated=falseという人工宣言だけで公表事実を証明しない |
| 対象期間・ページの網羅性 | 要求範囲と期待ページ集合、終了の根拠、件数の定義 | 中間ページ欠落、重複ページ、順序変更、空応答、範囲外行 | expected_codes一致だけで全期間や市場全体を網羅したと扱わない |
| 取込runと訂正履歴 | run識別・行識別・原本hash・訂正元・再実行の同一性 | 同一入力NO_OP、同一識別で内容変更、訂正元欠落、後続取込後の過去来歴保持 | 最新runの値で過去推定行を確認済みへ昇格しない |
| 永続化 | 新専用homeのschema、保存単位、途中失敗時の契約 | 書込前拒否、割込み、重複実行、接続解放、旧home不変 | 複数DBの一括原子性や自動移行を推測しない |

人工manifestのメモリ内検査は[STRICT_COVERAGE.md](STRICT_COVERAGE.md)のstrict_coverage_v1として実装した。期待ページ集合と全ページ横断の銘柄日付集合を別々に比較する。ページごとの行所属、継続tokenの正当性、期待集合自体の正しさは証明しない。既存strict_input_v1の価格原本と同一データであることの結合検査も残る。

選択価格に限った原本参照の結合は[STRICT_PRICE_COVERAGE.md](STRICT_PRICE_COVERAGE.md)として実装した。原本から銘柄日付を導くため、利用者が別途作った行一覧だけを根拠にしない。全履歴や提供元ページングへの結合とは区別する。

記録された継続キーの検査は[V2_PAGE_CHAIN.md](V2_PAGE_CHAIN.md)として実装した。これは録画された連鎖内の不足を検出するもので、実際の取得が正当だったことやページ間の同一時点性を証明しない。公式資料で途中更新の一貫性が保証されない点を確認済み。

次に必要なのは、明示的な価格鮮度・単元有効期間・公表時刻の根拠を保存する契約である。価格鮮度の日数や営業日規則を推測して固定しない。schemaを追加する場合は現行v1入力へ必須キーを後付けせず、別の入口または版として互換を保つ。外部サービスの項目意味を確定するには提供元資料か非機密原本の根拠が必要で、人工fixtureの成功は代用にならない。

単元・イベントの宣言適用期間を選択原本の値へ結ぶ検査は[STRICT_VALIDITY.md](STRICT_VALIDITY.md)として実装した。これは期間が基準時点を含むかの人工検査で、当時その証拠を入手できたことや実市場の正当性を証明しない。保存・訂正・観測時刻の次の契約案は[STRICT_EVIDENCE_STORAGE_PLAN.md](STRICT_EVIDENCE_STORAGE_PLAN.md)。現段階ではDB取込を実装しない。

DB保存・候補生成・通知への接続は本段階で行わない。今後も検査結果のready_for_live/current_signalはfalseを維持し、実通信なしで欠落・矛盾の拒否を先に確認する。
