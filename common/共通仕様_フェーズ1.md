## 3. データ契約（DuckDB）

DB ファイル: `${AI_TRADER_HOME}/market.duckdb`

```sql
CREATE TABLE listed (
  code TEXT PRIMARY KEY,       -- 4桁または5桁の銘柄コード（文字列）
  name TEXT, market TEXT,      -- "prime" / "standard" / "growth"
  sector33 TEXT, listed_date DATE
);
CREATE TABLE prices_daily (
  code TEXT, date DATE,
  open DOUBLE, high DOUBLE, low DOUBLE, close DOUBLE,
  volume DOUBLE, turnover DOUBLE,   -- turnover = 売買代金(円)
  adj_factor DOUBLE,                -- 調整係数（合成データでは1.0）
  PRIMARY KEY (code, date)
);
CREATE TABLE margin_weekly (
  code TEXT, date DATE,             -- 週末（金曜）基準日
  publish_date DATE,                -- 公表日。この日以降にのみ使用可
  long_balance DOUBLE,              -- 信用買残（株数）
  short_balance DOUBLE,             -- 信用売残（株数）
  PRIMARY KEY (code, date)
);
CREATE TABLE index_daily (
  name TEXT, date DATE, close DOUBLE, PRIMARY KEY (name, date)  -- "TOPIX"（合成では等金額指数）
);
CREATE TABLE calendar (
  date DATE PRIMARY KEY, is_business_day BOOLEAN
);
```

- J-Quants 実データを取り込む場合のマッピング: `/prices/daily_quotes` → prices_daily（`AdjustmentClose` 等の調整済み列を優先）、`/markets/weekly_margin_interest` → margin_weekly（`Date` を基準日、`publish_date = Date + 4暦日`（火曜公表想定。実データに公表日列があればそれを使う））、`/listed/info` → listed。
- **合成データモード**: `common/synth_data.py` の `build(seed=42)` が返す DataFrame 群をそのまま上記テーブルに入れる。両ビルドはこの同一データで比較する。

## 4. 戦略インターフェース

```python
from dataclasses import dataclass
from datetime import date

@dataclass
class Candidate:
    code: str
    side: str            # "BUY" のみ（フェーズ1）
    weight: float        # 目標比率（0〜1）。等金額なら 1/N
    score: float         # 戦略スコア（大きいほど優先）
    reason: str          # 日本語1行
    strategy: str
    strategy_version: str
    as_of: date          # シグナル計算に使った最終データ日
    holding_days: int    # 営業日
    limit_pct: float     # 前日終値に対する指値上限（例 0.005 = +0.5%）

class Strategy:
    name: str
    version: str
    rebalance: str       # "weekly_mon" | "daily" | "monthly"
    holding_days: int
    def universe(self, as_of: date, db) -> list[str]: ...
    def generate(self, as_of: date, db) -> list[Candidate]: ...
```

`generate` は **`as_of` 以前に入手可能なデータのみ**を使う（`margin_weekly` は `publish_date <= as_of`）。これに違反すると受入テストで落ちる。

### 4.1 戦略 A1 の確定仕様（両者同一）

- ユニバース: `listed.market in ("prime","standard")`、上場1年以上、直近60営業日平均売買代金 ≥ 1億円、`as_of` 時点で直近の margin_weekly が存在
- シグナル日: 毎週月曜（休場なら翌営業日）。`as_of` = その前営業日
- 指標: `chg4w = long_balance(最新) / long_balance(4週前) - 1`（`publish_date <= as_of` の中で最新）
- 5分位に分け、**chg4w が最も小さい分位（減少が最大）**を等金額で BUY。分位内は chg4w 昇順、最大 20 銘柄
- `holding_days = 20`、`limit_pct = 0.005`、リバランスは翌週の同タイミングで全入替（保有20営業日で自然に入替）
- パラメータは `config/strategies.yaml` に置き、既定値は上記

## 5. バックテスト規則（厳守）

1. シグナルは `as_of` の終値まででつくり、**エントリーは翌営業日（T+1）の寄り付き**
2. 指値: `limit = close(as_of) * (1 + limit_pct)`。`open(T+1) > limit` なら**未約定（スキップ）**。約定価格は `open(T+1)`
3. コスト: 手数料 0（楽天ゼロコース想定）、スリッページ **片道 0.1%**（買いは約定価格 ×1.001、売りは ×0.999）
4. イグジット: エントリーから `holding_days` 営業日後の**終値**。途中の損切り・利確はフェーズ1では無し
5. サイジング: 各リバランスで利用可能資金を候補数で等分（`weight`）。同一銘柄の重複保有なし。レバレッジなし。端株は無視（金額ベース）
6. 初期資金 10,000,000 円。日次で時価評価し `equity.csv` を出す
7. ベンチマーク: `index_daily` の TOPIX（合成では等金額指数）
8. 期間指定: `--from` `--to`（両端含む）。ウォークフォワードはフェーズ1では**単純な全期間＋年別集計**でよい

## 6. 指標定義（summary.json の必須キー）

```json
{
  "strategy": "margin_bucket_long", "version": "v1",
  "period": {"from": "2016-01-04", "to": "2026-08-31"},
  "initial_capital": 10000000,
  "final_equity": 0.0,
  "cagr": 0.0,                 // (final/initial)^(252/日数) - 1
  "sharpe": 0.0,               // 日次リターン平均/標準偏差 × sqrt(252)、rf=0
  "max_drawdown": 0.0,         // 負の値（例 -0.183）
  "trades": 0,                 // 約定したエントリー回数
  "skipped_by_limit": 0,       // 指値で未約定になった回数
  "win_rate": 0.0,             // 決済損益>0 の割合
  "profit_factor": 0.0,        // 総利益/総損失
  "avg_holding_days": 0.0,
  "benchmark_cagr": 0.0,
  "benchmark_max_drawdown": 0.0,
  "corr_to_benchmark": 0.0,    // 日次リターンの相関
  "yearly": {"2016": {"return": 0.0, "trades": 0}, "...": {}},
  "data_mode": "synthetic" | "jquants",
  "generated_at": "ISO8601"
}
```

`trades.csv` の列: `code, entry_date, entry_price, exit_date, exit_price, qty_yen, pnl_yen, pnl_pct, holding_days, strategy, reason`
`equity.csv` の列: `date, equity, cash, positions_value, benchmark`

## 7. CLI（両者同一。モジュール名は `aitrader`）

```
python -m aitrader init-db                          # スキーマ作成
python -m aitrader load-synthetic --seed 42          # 合成データ投入
python -m aitrader fetch --from 2024-01-01 --to 2026-08-31   # J-Quants（トークンがある場合のみ）
python -m aitrader signals --strategy margin_bucket_long --as-of 2026-08-29   # 候補をJSONで標準出力
python -m aitrader backtest --strategy margin_bucket_long --from 2016-01-04 --to 2026-08-31 --out results/
python -m aitrader report --results results/margin_bucket_long_v1/   # report.html 生成
```

## 8. 受入テスト（`common/tests/test_acceptance.py`）

テストは各ビルドのフォルダで `pytest ../common/tests -q` として実行する。テストは `aitrader` パッケージが次を提供することを前提とする。

```python
from aitrader.api import (
    init_db, load_synthetic, run_signals, run_backtest
)
# init_db(home: Path) -> None
# load_synthetic(home: Path, seed: int) -> None
# run_signals(home, strategy: str, as_of: date) -> list[dict]   # Candidate を dict 化
# run_backtest(home, strategy: str, start: date, end: date, out_dir: Path) -> dict  # summary.json の内容
```

テスト項目:

1. **スキーマ**: 5テーブルが存在し列名が §3 と一致
2. **決定性**: 同じ seed・同じ期間で2回 backtest → `final_equity`, `trades` が完全一致
3. **ルックアヘッド禁止**: `as_of` より後の `prices_daily` と `margin_weekly` を改変しても `run_signals` の結果が不変
4. **公表日の尊重**: `publish_date > as_of` の margin_weekly を使っていない（該当行を消しても結果不変）
5. **指値規則**: 合成データ中で `open(T+1) > close(as_of)*1.005` となる銘柄が `trades.csv` に現れない
6. **必須キー**: summary.json が §6 のキーをすべて持つ
7. **エクイティ整合**: `equity.csv` の最終行 `equity` と `final_equity` が一致し、`cash + positions_value == equity`（誤差1円）
8. **A1 仕様**: ある金曜 `as_of` の候補が 20 銘柄以下で、全員 side=BUY、chg4w が（ユニバースの絞り込み差を許容して）全銘柄中の下位30%以内に入る
