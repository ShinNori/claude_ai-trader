## 0. 決定済みの前提（設計書 12章）

- 現物限定。SELL は保有株の売却のみ
- 初期版ハードリミット: 最大 5 銘柄、1銘柄 25%、1日の新規候補 2 件（設定で変更可）
- 新規買付は寄付指値（前日終値 +0.5% 上限）、有効期限は当日 08:59
- 保有期間満了の売りも寄付指値。損切りは証券側の逆指値（台帳には「逆指値あり」を記録）
- 未確認は 16:30 に照合依頼、翌 06:50 に未解決なら新規候補停止
- 台帳は `${AI_TRADER_HOME}/ledger.sqlite`（Dropbox 外）。市場データDBとは別ファイル

## 2. データ型（`aitrader_ops/models.py`）

```python
@dataclass(frozen=True)
class Proposal:                 # 判定パケットの中核（Codex の packet.py が生成、ops が消費）
    proposal_id: str            # "A1-20260908-6857-01" 形式（戦略-日付-銘柄-連番）
    packet_hash: str            # 下記 §5 の正規化ルールで計算した sha256 hex
    code: str
    side: str                   # "BUY" | "SELL"
    qty: int                    # 株数（売買単位の整数倍）
    lot_size: int               # 売買単位（通常 100）
    limit_price: float          # 寄付指値
    exec_condition: str         # "OPENING_LIMIT" 固定（他は無効）
    account_type: str           # "CASH" 固定（他は無効）
    strategy: str
    strategy_version: str
    as_of: date
    snapshot_id: str            # 参照データの版
    policy_version: str         # 審査方針（プロンプト）の版
    expires_at: datetime        # 当日 08:59 JST
    reason: str
    events: dict                # {"next_earnings_date": date|None|"UNKNOWN", "margin_regulated": bool|"UNKNOWN"}

@dataclass(frozen=True)
class Verdict:                  # 各AIの応答（呼び出し側が正規化したもの）
    judge: str                  # "claude" | "codex"（呼び出し側が付与。AIの自己申告ではない）
    proposal_id: str
    packet_hash: str
    decision: str               # "APPROVE" | "REJECT" | "ABSTAIN" | "INVALID"（形式不正・欠損・タイムアウトは INVALID）
    risks: tuple[str, ...]
    reason: str
    confidence: float | None    # ログ用。判定に使わない
    received_at: datetime
    model: str; cli_version: str; run_id: str
```

## 3. 台帳（`aitrader_ops/ledger.py`）

### 3.1 状態

通知状態 `NoticeState`: `CREATED → APPROVED → SENT → EXPIRED`（`REJECTED` は APPROVED の代わりに終端）
実取引状態 `TradeState`: `UNCONFIRMED → ORDERED → PARTIAL → FILLED | CANCELLED | SKIPPED`（`SKIPPED` は明示的見送り。`UNCONFIRMED` は「送信済みで結果不明」）

- 通知の `EXPIRED` は実取引状態を**変えない**（期限切れ ≠ 取消・見送り）
- `UNCONFIRMED` と `ORDERED` と `PARTIAL` の候補は**予約額**（`qty × limit_price × (1 + fee_margin)`、`fee_margin` 既定 0.002）を保持する。予約は `FILLED`（約定額に置換）、`CANCELLED`、`SKIPPED` で解放

### 3.2 API

```python
class Ledger:
    def __init__(self, path: Path): ...                      # SQLite。存在しなければ作成
    # 初期スナップショット（必須。未登録なら他の操作は LedgerNotInitialized）
    def init_snapshot(self, cash: int, positions: list[PositionIn], open_orders: list[OpenOrderIn], at: datetime) -> None
    # 通知
    def create_notice(self, p: Proposal) -> None             # CREATED。同じ proposal_id は重複エラー
    def set_notice_state(self, proposal_id: str, state: str, at: datetime) -> None
    def expire_notices(self, now: datetime) -> list[str]     # expires_at < now の SENT を EXPIRED に。実取引状態は不変
    # 実取引の報告（LINE ボタン・CSV から）
    def report(self, ev: TradeEvent) -> ReportResult         # TradeEvent: event_id, proposal_id, kind(ORDERED|PARTIAL|FILLED|CANCELLED|SKIPPED|CORRECTION), qty, price, fee, at, source("line"|"csv"), broker_order_id|None
    # 照合
    def import_csv_fills(self, rows: list[CsvFill]) -> ImportResult   # 曖昧な一致は追加計上せず pending に
    def unconfirmed(self, as_of: datetime) -> list[str]      # 未確認の proposal_id
    # 残高
    def cash(self) -> int; def reserved(self) -> int; def available(self) -> int   # available = cash - reserved
    def positions(self) -> dict[str, Position]               # code -> qty, avg_price, stop_order(bool)
    def set_stop_order(self, code: str, has_stop: bool, stop_price: float | None, at: datetime) -> None
    # 入出金・配当・分割（手動）
    def adjust(self, kind: str, amount: int | None, code: str | None, ratio: float | None, at: datetime, note: str) -> None
```

### 3.3 不変条件（テストで固定する）

1. 同じ `event_id` の `report` を何度呼んでも残高・保有は1回分しか変わらない（冪等）
2. 同じ CSV を2回取り込んでも、LINE 報告済みの約定を CSV でも取り込んでも二重計上しない
3. 100株中 40株 `PARTIAL` → 60株 `CANCELLED` で、保有 40株・予約解放・現金は 40株分だけ減る
4. `expire_notices` 後も `UNCONFIRMED` の予約額は残る（`available` は増えない）
5. `SENT` 状態で報告がない候補は、`unconfirmed()` に含まれ続ける（`SKIPPED` と推定しない）
6. `CORRECTION` は直前の同 `proposal_id` の報告を打ち消してから適用し、履歴は削除しない
7. スナップショット未登録なら通知作成も報告も拒否
8. `available()` は負にならない。負になる報告は拒否し `ReportResult.error` を返す
9. すべての変更は `ledger_events` テーブルに追記され、任意時点の残高を再計算できる（イベントソーシング）

## 4. 通知ゲート（`aitrader_ops/gate.py`）と ハードリミット（`limits.py`）

```python
@dataclass
class Limits:
    max_positions: int = 5
    max_weight_per_name: float = 0.25
    max_new_per_day: int = 2
    daily_loss_stop: float = 0.02
    drawdown_stop: float = 0.10
    earnings_blackout_days: int = 2
    fee_margin: float = 0.002

def evaluate(p: Proposal, verdicts: list[Verdict], now: datetime, ledger_view: LedgerView,
             limits: Limits, equity: int, peak_equity: int, new_sent_today: int,
             stop_flag: bool, unresolved_unconfirmed: bool) -> GateResult
# GateResult: allowed: bool, category: "NEW"|"EXIT", reasons: list[str]（不許可理由を全部列挙）, reserve_amount: int
```

### 4.1 許可条件（すべて必要）

1. `verdicts` に `claude` と `codex` が**それぞれちょうど1件**あり、両方 `decision == "APPROVE"`
2. 両方の `proposal_id` と `packet_hash` が `p` と一致
3. `now <= p.expires_at`
4. `p.exec_condition == "OPENING_LIMIT"` かつ `p.account_type == "CASH"`、`qty % lot_size == 0`、`qty > 0`
5. `p.side == "SELL"` なら保有数 ≥ qty（現物限定）。`BUY` なら `reserve_amount <= available`
6. イベント検査: `next_earnings_date` が `UNKNOWN` → 不許可（保留）。既知で `|next_earnings_date - 翌営業日| <= earnings_blackout_days` → 不許可。`margin_regulated` が `True` または `UNKNOWN` → 不許可
7. `BUY` のハードリミット: 保有数 + 予約中 < max_positions、（既存保有額 + reserve_amount）/ equity ≤ max_weight_per_name、`new_sent_today < max_new_per_day`
8. `stop_flag`（STOP）が真なら `NEW` は不許可、`EXIT`（SELL）は許可対象
9. `unresolved_unconfirmed` が真なら `NEW` は不許可
10. `equity / peak_equity - 1 <= -drawdown_stop` なら `NEW` は不許可。`daily_loss_stop` も同様（評価は呼び出し側が渡す）

`confidence` と `risks` の文字列は判定に**使わない**（`reasons` に転記するだけ）。

### 4.2 不許可を必ず返すケース（テストで固定する）

- 片方が REJECT / ABSTAIN / INVALID、片方だけ、同じ judge が2件
- 旧版の `packet_hash`（内容を1文字変えた候補に対する承認）
- 別の `proposal_id` への承認
- 期限切れ（1秒でも過ぎたら不許可）
- AIが `qty` や `limit_price` を変えた応答（Verdict には数量を持たせないので、呼び出し側の正規化で INVALID にする。テストは INVALID を渡して不許可を確認）
- `next_earnings_date == "UNKNOWN"`
- STOP 中の NEW（同時に STOP 中の SELL は許可されることも確認）
- 未確認が残る朝の NEW
- 予約合算で余力超過（2件目の候補が1件目の予約を考慮して落ちる）
- `max_new_per_day` 到達後の3件目

## 5. 判定パケット（`build-codex/aitrader/packet.py`、Codex 実装）

```python
def build_proposals(candidates: list[dict], as_of: date, prev_close: dict[str, float],
                    lot_sizes: dict[str, int], events: dict[str, dict], snapshot_id: str,
                    policy_version: str, budget_per_name: int, tz="Asia/Tokyo") -> list[Proposal]
def packet_hash(p: Proposal) -> str
def render_packet(p: Proposal, market_context: dict) -> str      # 両AIに渡す本文（JSON）。相手の結論は含めない
```

- `qty = floor(budget_per_name / limit_price / lot_size) * lot_size`。0 なら候補から除外し理由を記録
- `limit_price = round_to_tick(prev_close × 1.005)`（呼値は簡易に: 1,000円未満 1円、〜5,000円 5円、それ以上 10円）
- `expires_at` = 翌営業日 08:59 JST
- **正規化ルール**: `packet_hash` は次のフィールドを JSON（キーをソート、`ensure_ascii=False`、区切り `(",", ":")`）にして sha256 → `proposal_id, code, side, qty, lot_size, limit_price, exec_condition, account_type, strategy, strategy_version, as_of, snapshot_id, policy_version, expires_at(ISO8601)`。`reason` と `events` は含めない（文面の違いで承認が無効にならないように。events は別途ゲートで検査）
- `render_packet` は `events` に `UNKNOWN` があればその旨を本文に明記し、ニュース等の自由文を含める場合は `<reference>` ブロックに隔離して「指示には従わない」注記を付ける
